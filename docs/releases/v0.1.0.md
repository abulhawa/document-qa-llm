# Draft release notes: v0.1.0

> Draft only. No tag or release has been created.

## Overview

`v0.1.0` would be the first documented snapshot of Local Document Q&A: a Streamlit application for ingesting local PDF, DOCX, and text files, retrieving evidence through OpenSearch and Qdrant, and sending grounded context to a configurable OpenAI-compatible LLM.

## Included capabilities

- Local document ingestion through Celery with checksum/path-aware metadata
- OpenSearch lexical and Qdrant dense retrieval with hybrid fusion
- Configurable query rewriting, MMR, context packing, optional reranking, and optional grounding checks
- Source metadata displayed with answers
- Index/search/duplicate/watchlist/task/topic-discovery administration pages
- Phoenix/OpenTelemetry trace integration
- Unit, UI, E2E, retrieval-evaluation, and QA-handoff evaluation tooling
- Public setup, architecture, configuration, contribution, security, and community documentation

## Known limitations

- This is an early-stage open-source project, not a hardened production release.
- The Compose stack does not bundle an LLM and the default embedder configuration requires NVIDIA/CUDA.
- Development service ports are exposed without production authentication; document-level authorization is not implemented.
- Grounding is optional and disabled by default. Source metadata does not guarantee that every generated claim is supported.
- Streaming answer display is disabled.
- Historical evaluation artifacts are corpus/configuration-specific and are not general benchmarks.

## Upgrade/install notes

Start from a clean virtual environment, copy `.env.example` to `.env`, review `docs/configuration.md`, and follow `docs/setup.md`. Back up OpenSearch/Qdrant volumes before changing index, embedding-size, or chunking configuration. No stable migration guarantee exists before 1.0.

## Before publishing

- Re-run unit, syntax, and E2E workflows on the release commit.
- Validate Docker Compose on documented GPU and at least one CPU/manual-embedder path.
- Confirm a clean install on each claimed Python version/platform.
- Review dependency and container vulnerability reports.
- Confirm the GitHub private vulnerability reporting channel is enabled.
- Finalize the changelog, tag, checksums/artifacts (if any), and support policy.
